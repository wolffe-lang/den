# Formats

This is an implementation map from the Git 2.56.0 documentation sections in
SOURCES, with measurements from the pinned oracle. It is not VCS code.
Nineteen Git pages/manuals were consulted; the normative sections are named
below. Byte examples are generated by `tools/formats` from the corpus and
stored as hex, never hand-entered.

## Repository layout

**gitrepository-layout(5), Description and named entries;
technical/repository-version.adoc, Versions 0/1.** A working repository has
`.git/`; a bare one is its own administrative directory. A gitfile starts
`gitdir: ` and points elsewhere; do not require .git to be a directory when
locating repositories. HEAD is a symref such as `ref: refs/heads/main\n`, or
a detached oid. Loose refs are newline-terminated hex ids; packed refs and
reflogs require separate parsers. Objects live under two-hex fanout paths;
refs/heads, refs/tags, refs/remotes, config, info/exclude, index and logs are
the MVP state. Worktrees, modules, alternates and shallow state are deferred.
Unknown repository versions/extensions must be refused, not opened for writing.

## Object bodies and loose objects

**Git user manual, The Object Database and Object storage format;
gitformat-loose(5), Loose objects; git-commit-tree(1), Commit Information;
i18n.adoc; git-mktag(1), Tag Format; gitformat-signature(5), Description,
Commit/Tag signatures.**

The hashed input is ASCII type, SP, decimal byte size, NUL, then body bytes.
The complete hashed input is zlib-compressed for a loose object. The oid is
SHA-1 of the uncompressed header+body, never a hash of the compressed file.
Empty blobs and empty trees have distinct 7-byte raw forms and 15-byte loose
files. Blob bodies are uninterpreted bytes, including NUL and invalid UTF-8.

A tree body repeats octal mode, SP, non-NUL basename, NUL, raw object id
(20 bytes for SHA-1). No newline separators or hex ids. Tree order is unsigned
byte order, treating a directory name as though a slash followed it: directory
`a` sorts after file `a.c` and before `a0`. `mktree` receives deliberately
unsorted entries in the ordering witness; `cat-file tree` supplies the raw
result. Regular modes are 100644/100755, symlinks 120000, subtrees 40000;
gitlinks 160000 are deferred. Paths cannot contain NUL or slash within an entry.

A commit writes tree first, zero or more parent headers in parent order,
author, committer, optional headers, blank line, then message bytes. Identity
headers carry name/email, epoch seconds and signed numeric zone. Preserve
unknown headers and continuation lines when reading: `gpgsig` continuation
lines begin SP, even for an embedded empty line. Signing is deferred.
`encoding` identifies non-UTF-8 commit messages; absent means UTF-8. Never
silently recode stored objects. The fixed identity/date determine oids.

An annotated tag uses object/type/tag/tagger headers then a blank line and
message, possibly followed by an armored signature. A lightweight tag is
only a ref, not a tag object. mktag validates more strictly than generic
hash-object; its extra-header and missing-tagger errors need separate cases.

**Measured loose compression.** Default matches zlib level 1, not level 6,
on the recorded payload. `core.compression=9` changes it; explicit
`core.looseCompression=0` overrides it. Raw summary includes sizes and hashes.
No compression-byte equivalence is inferred from equal oids. Adopted R-vc00-2
requires raw bytes and oid equality plus interoperable compression and a
per-corpus size ratio <=1.25 against Git level 1. `loose-object-raw` is the
named harness comparison mode; checksum or oid corruption still fails.

### Object plumbing measurements (Git 2.56.0)

With the pinned empty template, plain init writes HEAD (21 bytes for main) and
config (92 bytes), bare config is 66 bytes. The created Git directories are
objects/info, objects/pack, refs/heads and refs/tags; the parents are implicit.
There is no description or info/exclude under that template. Den additionally
creates an empty hooks directory as specified. No sample hook was consulted.
Both file inventories and reinit output are retained in vc02-oracle.json.

With identity `a <a>`, timestamp `0 +0000`, empty message and empty tree, a root
commit body is **92 bytes**. The tag `t` targeting the empty blob, same tagger,
is **86 bytes**. These are measured examples of minimal inputs, not a claim of
a global mathematical minimum. Empty blob/abc blob/empty tree IDs agree with
the predicted well-known values.

Commit-tree reads stdin and -F files byte-exactly with respect to final newline;
-m adds a missing final LF, and each further nonempty paragraph gets one
separator LF. A NUL message exits 1 with
`error: a NUL byte in commit log message not allowed.` and writes no object.

The i18n.adoc Discussion says commit creation deliberately avoids recoding.
The pinned binary nevertheless repairs invalid UTF-8 when no non-UTF-8 encoding
is configured. R-vc02-2 adopts the measured command-edge behavior, while generic
hash-object/store/cat-file APIs preserve bytes. The isolated byte ff gives:

| Environment/config | commit-tree stdin | commit-tree -F file | mktag message |
|---|---|---|---|
| LC_ALL=C, no encoding | c3 bf, warning | c3 bf, warning | ff, no warning |
| LC_ALL=C.UTF-8, no encoding | c3 bf, warning | c3 bf, warning | ff, no warning |
| LC_ALL=C, i18n.commitEncoding=ISO-8859-1 | ff, encoding header, no warning | ff, encoding header, no warning | ff, no warning |

The exact warning is:

```text
Warning: commit message did not conform to UTF-8.
You may want to amend it after fixing the message, or set the config
variable i18n.commitEncoding to the encoding your project uses.
```

Valid UTF-8 subsequences survive; isolated invalid octets are encoded as Latin-1
scalars. Overlong and surrogate-shaped sequences are repaired bytewise.
`encoding-measure.json` and `encoding-paths.json` retain exact oracle bytes;
native and release integration gates compare all nine command/environment paths.
No reviewed difference is needed because the tested CLI behavior matches Git.

## Index v2 (v3/v4 reading later)

**gitformat-index(5), Header, Index entry, Extensions.** Network byte order;
DIRC, u32 version, u32 entry count. Each v2 entry has ten u32 stat words:
ctime seconds/ns, mtime seconds/ns, dev, ino, mode, uid, gid, size. Then the
raw oid and u16 flags (assume-valid, extended=0 in v2, stage, 12-bit name
length). NUL-terminated path plus padding makes the complete entry a multiple
of eight bytes, with at least one terminating NUL. A SHA-1 trailer hashes all
preceding index bytes. Entries sort by unsigned path bytes, then stage 0–3.
Mode combines type and executable permission; only regular 0644/0755 matter.
The native stat probe provides every needed word; size/dev/ino fields use low
32 bits. v3 adds extended flags; v4 prefix-compresses names and drops padding.

Optional uppercase extensions can be skipped by their declared sizes:
TREE (cache tree), REUC (resolve undo), UNTR (untracked cache), FSMN (fsmonitor),
EOIE (end of entries), IEOT (entry offset table). Lowercase mandatory `link`
(split index) and `sdir` (sparse directories) require explicit refusal until
implemented; unknown mandatory extensions also refuse. Skipping a cache is
not permission to discard semantic state or rewrite a format not understood.

## Pack v2, idx v2, deltas

**gitformat-pack(5), pack files, Object types/encoding, Size encoding,
Deltified representation; Version 2 idx.** PACK, u32 version=2, u32 object
count, entries, SHA-1 pack checksum. Entry header first byte carries continuation,
3-bit type and 4 size bits; subsequent groups add seven low-to-high size bits.
Types 1/2/3/4 are commit/tree/blob/tag; 6 is OFS_DELTA, 7 REF_DELTA; 0 invalid,
5 reserved. Each body is a separate zlib stream without the loose-object
header. OFS base distances use the offset encoding (not the little-endian
size varint); REF bases use raw oids. Reconstruct the type/size/NUL header to
verify the resulting object's oid.

Delta data has base-size and result-size varints, then copy/insert instructions.
Copy high bit is set; seven presence bits select four little-endian offset
and three size bytes. Missing bytes are zero; zero copy size means 65536.
Insert opcode 1–127 is literal length; opcode zero is invalid. Validate source
and result bounds, exact result size, chain depth, and thin-pack external bases.
OFS bases may themselves be deltas. Persisted packs must be self-contained.

idx v2: ff 74 4f 63, version=2, 256 u32 cumulative fanout words, sorted raw
oids, CRC32 per packed entry, 31-bit offsets or high-bit references to u64
offsets, then pack checksum and index checksum. All fixed multibyte values are
network order. CRC32 covers entry header, base descriptor and compressed bytes.
Pack-byte equality is not the target: git must read/fsck the result, with the
1.5x corpus-size cap. Reverse indexes, mtimes, MIDX and bitmaps are deferred.

**gitformat-commit-graph(5)** describes CGPH plus chunk lookup, fanout/oid/data,
optional generation/Bloom/base chunks and checksum. It is an acceleration
cache, deferred: walk commit parents instead. **gitformat-bundle(5), Format/
Semantics/Capabilities** describes v2/v3 textual header, prerequisites, refs
and pack. Bundles and unknown required capabilities are explicitly unsupported.

## Wire framing, negotiation and transports

**gitprotocol-common(5), pkt-line; gitprotocol-v2(5), framing, requests,
capabilities, ls-refs, fetch; gitprotocol-pack(5), Transports and negotiation;
gitprotocol-capabilities(5), Description and named capability sections.**

Four ASCII hex length bytes include themselves. Maximum packet length 65520;
payload may be binary. 0000 flush, 0001 v2 delimiter, 0002 stateless response-end;
0004 is empty data and is not flush. Accept missing trailing LF on text packets.
Length underflow, reserved/oversized packets and truncation need named errors.

For git://, send a framed upload-pack pathname request, NUL host parameter,
extra NUL then `version=2` NUL. File/ssh request v2 through GIT_PROTOCOL;
ssh is a system executable with pipe plumbing, never a shell-joined arbitrary
command line. V2 advertises version 2 and capabilities then flush; request is
command=NAME, selected advertised capabilities, delimiter, arguments, flush.
Unknown advertised keys may be ignored; never request unsupported capabilities.

ls-refs supports symrefs, peel, ref-prefix (filter again client-side) and unborn
when advertised. Fetch sends want/have, optional thin-pack/ofs-delta/no-progress,
and done. Response sections include acknowledgments (ACK/NAK/ready), optional
shallow/wanted-refs/URI sections and packfile. With done, acknowledgment section
is omitted. Pack data is sideband framed: channel 1 bytes, 2 progress, 3 fatal.
Thin packs require missing-base handling before writing a self-contained pack.
Shallow, filter, packfile URIs and old-version fetch negotiation are deferred.

Traditional receive-pack push advertises refs plus NUL capabilities on the
first line; send old/new/ref commands, NUL capabilities on first command, flush
and pack. Deletion-only sends no pack; create/update sends one even if empty.
Report status begins unpack ok/error, then ok/ng per ref, then flush. Ref old
ids must be checked to prevent races. v2 has no documented push command here:
R-vc00-3 proposes this narrow exception to the deferred v0/v1 fetch surface.

## Config, ignores, revisions, hooks

**git-config(1)/config.adoc, Syntax and Includes.** Sections/variable names are
case insensitive, quoted subsections case sensitive. SP/HT handling, #/;
comments, quoted strings, backslash line continuation, \n/\t/\b/\"/\\ escapes,
implicit true, multivalues and last-definition precedence need byte tests.
Includes insert at the include position, relative to their config file; includeIf
is separately staged. The pinned config's exact bytes are tracked as evidence.

**gitignore(5), Description and Pattern Format.** Precedence: command line,
nearest per-directory .gitignore, info/exclude, core.excludesFile. Last match
within a source wins. Tracked files are unaffected. Leading # comments, !
negation, escaped trailing spaces and leading metacharacters matter. Slash
anchors relative to the ignore file; trailing slash matches only directories.
`*`/`?`/brackets do not cross slash; ** has the documented leading, trailing,
and middle directory cases. A negation cannot reinclude a child whose parent
is excluded. Do not follow symlinked .gitignore files.

**gitrevisions(7)/revisions.adoc, Specifying Revisions and Ranges.** Resolve
full/unambiguous oid prefixes and refs with documented disambiguation order;
HEAD/@, parent ^n, first-parent ~n, typed dereference, ref@{n}, @{-n}, and
rev:path. a..b is reachable(b) minus reachable(a); a...b is symmetric difference
excluding all merge bases. Multiple ranges form one set for ordinary walks,
not independent ranges. Stage:path addresses index conflict stages.

**githooks(5), Description and selected hooks.** Hooks and user editors are
not executed in the MVP. core.hooksPath points to an empty harness directory;
GIT_EDITOR=false. Sample hook scripts were neither read nor copied into the
corpus. Commit signing and credential helpers are also deferred.

## Measured porcelain bytes

The appendix is generated from the exact Git side of the differential runs:
log default (two commits), --oneline (merge history), dirty status short/long,
unified diff, rename diff, default blame. Colours/pagers are disabled. Default
log includes full commit id, Author, Date and four-space message indentation;
--oneline has abbreviated ids and subjects. Unified diff includes diff --git,
index old..new and mode, ---/+++ and @@ hunks; pure rename has similarity and
rename-from/to instead. Blame includes boundary caret, abbreviated id, author,
numeric zone, line number and source. These are observations, not descriptions
substituted for byte fixtures. Mode-change and binary examples are also measured in the appendix; these
are format witnesses, not additional den parity cases.
