P1. git fsck, default severities (plain). Every identity id in
  fsck-msgids is an ERROR, so a shape git reports makes fsck exit nonzero
  with `error in commit <id>: <msgId>: <text>` (and in tag for the
  tagger). Predicted id per shape:
    control, zero-date, latin1-name: clean.
    empty-email: clean. No id names an empty email: missingEmail is an
      absent <...>, badEmail a malformed one. This is the witness's shape,
      so the prediction is that git fsck itself accepts 5f453914.
    over-i64: clean (the date fits an unsigned 64-bit timestamp).
    zone-minutes: clean (fsck checks the zone's form, not its range).
    empty-name, empty-both: badName.
    no-name: missingNameBeforeEmail.
    no-email: missingEmail.
    glued-email, lt-in-name: missingSpaceBeforeEmail.
    gt-in-name: badName.
    lt-in-email: badEmail.
    glued-date, gt-in-email, no-date: missingSpaceBeforeDate.
    two-spaces, negative: badDate.
    zero-padded: zeroPaddedDate.
    over-u64: badDateOverflow.
    zone-long, zone-short, zone-unsigned, trailing, cr: badTimezone.
P2. git fsck --strict: identical to plain for every shape. The page says
  --strict adds the g+w file mode check; no identity id changes severity.
P3. git clone and fetch with their defaults (transfer.fsckObjects false):
  every shape clones over file:// (upload-pack, index-pack and the
  connectivity check), with exit 0 and no message. With
  transfer.fsckObjects=true (or fetch.fsckObjects=true) git refuses each
  shape P1 names, naming the msg id, and clones the clean ones.
P4. git reading, every shape, exit 0:
  a. cat-file -p prints the object's bytes unchanged.
  b. log, show (medium, full, fuller) print `Author: <name> <<email>>`
     from the line's own bytes, the latin1 byte unchanged; a date that
     does not parse prints as the epoch, `Thu Jan 1 00:00:00 1970 +0000`;
     no shape is refused.
  c. %an/%ae/%al are the name, the email and its local part as split at
     the first `<` and the following `>`; %ae is empty for empty-email.
  d. blame (default and --porcelain) prints every shape.
P5. git writing:
  a. An explicitly empty email (`-c user.email=` or GIT_AUTHOR_EMAIL set
     empty) is accepted by commit, commit-tree and tag -a, writing `<>`.
  b. An empty name is refused by name: `fatal: empty ident name (for
     <e@example.invalid>) not allowed`, exit 128.

P6. den at the base, from its sources:
  a. Receive (clone and fetch on every transport, and serving a fetch or
     a push: the shared closures run packcmd.links, which runs
     commit_format.parse_identity on every identity line) and den fsck:
     refused `Unsupported(fsck identity diagnostics)`: empty-email,
     empty-name, no-name, empty-both, no-email, no-date, negative,
     over-i64, over-u64, zone-short, zone-unsigned, zone-minutes,
     lt-in-name, gt-in-name, lt-in-email, gt-in-email, trailing;
     `Unsupported(fsck identity bytes)`: latin1-name.
     Accepted: control, zero-date, glued-email, glued-date, two-spaces,
     zero-padded, zone-long (a six-character zone parses), and cr if
     wolf's trim takes CR as whitespace.
     So den refuses shapes git clones (every one), and accepts shapes git
     fsck reports (glued-email, glued-date, two-spaces, zero-padded,
     zone-long).
  b. cat-file -p: the raw bytes, equal to git's for every shape.
  c. log and show: pretty.identity prints the bytes up to the last `>`,
     so the empty-email witness prints as git does (`walker0643 <>`).
     Refused: latin1-name (not UTF-8), no-email and no-date (no `>` or
     no date words), trailing (three words), over-i64 and over-u64 (no
     64-bit int), negative (date range), zone-long and zone-short (zone
     length), zone-minutes (`history noncanonical timezone`). Where git
     prints the epoch for a bad date, den refuses.
  d. --format=%an etc.: refused for every shape, control included
     (`history pretty format:...`); den has no user formats.
  e. blame: refuses no-name (no byte before the `<`) and the date shapes
     log refuses.
  f. Writing: den commit and commit-tree refuse an empty email and an
     empty name with their own named refusals (`commit missing author
     identity`, `commit-tree identity/date`), never Git's message.
