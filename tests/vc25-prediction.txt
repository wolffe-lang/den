== 2. The on-disk layout (measured from the pinned Git; den writes the same) ==

After `clone --recurse-submodules URL DIR` (probe 1 steps clone-recurse,
dump-clone-recurse):
  DIR/.git/config: `[submodule]` `active = .` immediately after `[core]`
    (before `[remote "origin"]`); `--recurse-submodules=P` writes
    `active = P` per pathspec (a pathspec that matches nothing clones none,
    probe 2 clone-pathspec-none). Then one `[submodule "<name>"]` with only
    `url = <resolved>` per submodule, in index (path) order.
  `submodule init` without submodule.active writes `active = true` and
    `url = <resolved>` per submodule, in index order.
  DIR/<path>/.git: a file, `gitdir: <relative path to the gitdir>\n`, e.g.
    `gitdir: ../.git/modules/abs`, `gitdir: ../../../.git/modules/midname/modules/leafsub`.
  DIR/.git/modules/<name>/: a non-bare gitdir (HEAD, config, index, logs,
    objects, packed-refs, refs; the empty template adds nothing else),
    keyed by name, not path; a name with `/` nests directories. Nested
    submodules live under the parent's gitdir:
    .git/modules/<name>/modules/<nested-name>.
  .git/modules/<name>/config: [core] repositoryformatversion 0, filemode,
    bare = false, logallrefupdates, `worktree = <relative path from the
    gitdir to the worktree>` (`../../../abs`, `../../../../../mid/deps/leaf`);
    [remote "origin"] with the resolved URL and the default fetch refspec;
    [branch "<remote HEAD's branch>"] tracking it; and, in a superproject
    submodule, its own nested `[submodule "<n>"] active = true url = …`.
  The submodule's HEAD is detached at the gitlink (`<sha>\n`); its
    refs/heads/<default> exists (made by the clone), refs/remotes/origin/HEAD
    is symbolic, packed-refs holds refs/remotes/origin/<branch>. Its HEAD
    reflog has `clone: from <url>` then `checkout: moving from <branch> to <sha>`.
  extensions.submodulePathConfig and submodule.<name>.gitdir: not written
    (init.defaultSubmodulePathConfig is false by default); a repository with
    the extension stays refused by name (den refuses unknown extensions).
  The superproject's index: a gitlink entry carries the submodule
    directory's own lstat words (ctime, mtime, dev, ino, uid, gid, size;
    4096 on the probe's file system), mode 160000, the commit id; a fresh
    empty directory for an unpopulated submodule; all stat words zero after
    a mixed reset re-reads it from the tree (probe 2 idx-*).
  den's reflogs in .git/modules/*/logs inherit R-vc18-2 (den's transport
    identity, a zero date, bare messages): those paths are KNOWN, named
    differences, as .git/logs is today; every other byte is compared.

Relative URLs (probe 1 rel-*, 171 resolutions): resolved against the
remote of the current branch's upstream (`branch.<b>.remote`), else
origin, else the superproject's own top-level directory with
`warning: could not look up configuration 'remote.origin.url'. Assuming this
repository is its own authoritative upstream.`; nested relatives against
the immediate superproject's resolved URL. Rules the rows hold, each from
the matrix: one trailing `/` of the remote is dropped; `./` appends;
each leading `../` strips one component, through `scheme://host`
(https://h.example + ../x.git -> https://x.git, + ../../y -> https:/y/x.git)
and through an scp-like host (git@h:o/top.git + ../../../x.git ->
`.:x.git`); a relative remote strips to `.` and then fails
`fatal: cannot strip one component off url '.'` (or `'..'`), exit 128;
`../x/` loses its trailing slash; inner `./` and `../` after the first
non-dot component are kept verbatim; `.././x` == `../x`; file:// and plain
paths follow the same component rules.

== 4. Behaviour, per command (git's form measured; den's the same unless named) ==

Reading (item 3):
  ls-tree [-r] [-t] [-d] [--name-only] [-z] TREE-ISH [PATH…] and
    ls-files [-s] [-z] [PATH…]: new bounded commands; a gitlink prints
    `160000 commit <id>\t<path>` and `160000 <id> 0\t<path>`.
  cat-file -p of a tree: unchanged (already exact). cat-file -t/-p of a
    gitlink's id absent from the store: `fatal: git cat-file: could not get
    object info` / `fatal: Not a valid object name <id>`, exit 128 (rows
    check den's existing missing-object forms against these).
  show REV:<gitlink path>: `fatal: bad object REV:path`, exit 128.
  diff/log/show: a gitlink side is the text `Subproject commit <id>\n`,
    `-dirty` appended for a worktree side with modified tracked content;
    `index a..b 160000`, `new file mode 160000`, `deleted file mode
    160000`; a typechange prints a deletion and an addition, `T` in
    --raw/--name-status; --stat counts the one line (`sub | 2 +-`, a
    dirty-only side `mid | 0`); --raw shows the worktree side as 0000000.
    Untracked content alone produces no diff.
  --submodule=short (default), =log and =diff, and diff.submodule:
    `Submodule <path> <a7>..<b7>:` then `  > subject` per commit (`  <` and
    ` (rewind):` backwards), `<a7>...<b7> (commits not present)`,
    `0000000...<b7> (new submodule)`, `<a7>...0000000 (submodule deleted)`,
    `Submodule <path> contains modified content` (untracked content
    alone prints nothing by default; its form under
    --ignore-submodules=none is measured before its row is written);
    =diff prints the submodule's own diff with `<path>/` prefixes. The log
    walk is the submodule's own repository.
  --ignore-submodules[=none|untracked|dirty|all] and submodule.<name>.ignore
    (.gitmodules, overridden by .git/config, overridden by the option).
  status, long: `modified:   <path> (new commits[, modified content][,
    untracked content])`, and the extra hint line `(commit or discard the
    untracked or modified content in submodules)` when content is dirty;
    short: ` M` new commits, ` m` modified content only, ` ?` untracked
    only, applied recursively (a nested submodule's untracked file is `?`
    or rolls into `M`); porcelain v1 (and -z): ` M` for every change;
    staged gitlinks `M ` / `A ` / `D `; `MD` when the directory is gone.
    An uninitialised submodule (empty directory) is clean. status.submoduleSummary
    stays a named refusal (R-vc25-8).
  An untracked nested repository is an untracked directory `dir/`, as Git
    shows it (the scan.lu:255 refusal goes, R-vc25-11).
Clone and the submodule command (item 4):
  clone --recurse-submodules[=<pathspec>] URL DIR: the superproject clone
    as today, `submodule.active` as above, then `submodule update --init
    --recursive`. stderr: `Submodule '<name>' (<url>) registered for path
    '<path>'` for each, `Cloning into '<absolute path>'...` for each, nested
    after their parent; stdout: `Submodule path '<path>': checked out
    '<sha>'`. -q silences both. A failed submodule leaves the superproject
    clone in place and exits nonzero: a clone failure retries once
    (`Failed to clone '<path>'. Retry scheduled`, then `Failed to clone
    '<path>' a second time, aborting`, exit 1); a missing commit exits 128.
    --shallow-submodules, --remote-submodules, -j/--jobs and --reference stay
    named refusals.
  submodule [status [--cached] [--recursive] [PATH…]]: ` `/`-`/`+`/`U`,
    the id, the path relative to the cwd, and ` (<describe>)` when
    populated: an annotated tag (`v1`, `v1-2-g750544b`), else any ref
    (`heads/main`, `remotes/origin/HEAD`, `heads/main-2-g39f0fa7`), else
    the abbreviated id; den gains an internal describe for this (R-vc25-6).
    No mapping for a gitlink: `fatal: no submodule mapping found in
    .gitmodules for path '<p>'`, exit 128.
  submodule init [PATH…]: `Submodule '<name>' (<url>) registered for path
    '<path>'`, existing entries untouched, update copied unless `!cmd`.
  submodule update [--init] [--recursive] [--remote] [-N] [--checkout]
    [--force] [PATH…]: clones a missing submodule into .git/modules/<name>,
    checks out the recorded commit on a detached HEAD (`Submodule path
    '<p>': checked out '<sha>'`), does nothing for one already there; a
    recorded commit not reachable from any ref is fetched first, then
    fetched directly by id (`Unable to fetch in submodule path '<p>';
    trying to directly fetch <sha>:`, `fatal: Fetched in submodule path
    '<p>', but it did not contain <sha>. Direct fetching of that commit
    failed.`, exit 128); local changes in the way: the checkout refusal then
    `fatal: Unable to checkout '<sha>' in submodule path '<p>'`, exit 1;
    --force checks out anyway. --remote fetches and uses
    origin/<submodule.<name>.branch, .git/config over .gitmodules, else the
    remote HEAD>; `branch = .` follows the superproject's branch.
    --merge, --rebase, update = merge|rebase|!cmd stay named refusals;
    update = none skips (R-vc25-7). An unknown path: `error: pathspec
    '<p>' did not match any file(s) known to git`, exit 1.
  submodule sync [--recursive] [PATH…]: `Synchronizing submodule url for
    '<displaypath>'`, rewriting submodule.<name>.url and the submodule's
    remote.origin.url from .gitmodules (relative URLs re-resolved); only
    initialised submodules.
  submodule foreach [--recursive] [-q] COMMAND: `Entering '<displaypath>'`,
    the command through `sh -c` with $name, $sm_path, $path, $displaypath,
    $sha1 and $toplevel; a nonzero exit stops with `fatal: run_command
    returned non-zero status for <displaypath>\n.`, exit 128. Without a
    /bin/sh, a named refusal.
  Relative URLs as in section 2; `submodule.<name>.url` written after init.
  Every transport den speaks for the submodule clone and fetch: file://,
    local paths, git://, ssh (scp-like and ssh://) and https, under the
    protocol policy below.
Transports (item 5):
  protocol.allow / protocol.<name>.allow (always, never, user) and
    GIT_PROTOCOL_FROM_USER, for every den transport; commands the
    submodule machinery runs are not from the user, so file:// and plain
    paths refuse by default exactly as Git does (`fatal: transport 'file'
    not allowed`). Every file-transport row passes protocol.file.allow=always.
  url.<base>.insteadOf (longest match; the stored URL stays the original,
    probe 1 insteadof-*) and url.<base>.pushInsteadOf (push only; ignored
    for a remote with pushurl), for clone, fetch, pull, push and the
    submodule machinery; `remote get-url --push` shows the rewrite.
  Anonymous https: already prompts only on a 401 (http/client.lu); rows
    prove a public recursive clone sends no Authorization and never reads
    the terminal.
Working in the repository (item 6):
  checkout/switch/reset/pull without recursion: the gitlink changes in the
    index; the submodule's worktree is never touched; a newly appearing
    gitlink gets an empty directory; a disappearing one keeps a populated
    directory with `warning: unable to rmdir '<p>': Directory not empty`
    (it is then untracked `<p>/`); checkout's path list prints `M\t<p>`.
  --recurse-submodules or submodule.recurse=true on checkout, switch,
    reset and pull: populated, active submodules follow the recorded commit
    (detached), recursively; a removed gitlink's worktree goes, its gitdir
    stays; refusals as measured (`error: Submodule '<p>' could not be
    updated.`). pull --recurse-submodules prints `Fetching submodule <p>`
    and the update's `checked out` lines; submodule.recurse=true pull
    updates silently (both measured).
  fetch (and pull's fetch): on-demand by default: after the superproject's
    fetch, each populated submodule whose newly fetched gitlinks name a
    commit it lacks is fetched (`Fetching submodule <displaypath>`);
    --recurse-submodules[=yes|on-demand|no], --no-recurse-submodules,
    fetch.recurseSubmodules, submodule.<name>.fetchRecurseSubmodules.
  merge (pull's merge and rebase, rebase, cherry-pick, revert): a gitlink
    changed on one side only takes that side; unchanged passes through;
    both moved differently stays a named refusal (R-vc25-9).
  add <path> / add -A / add . / commit -a: stage the submodule's HEAD as
    the gitlink when it moved; modified or untracked content alone stages
    nothing; `add <submodule>/<file>`: `fatal: Pathspec '<p>' is in
    submodule '<s>'`.
  reset --hard: restores gitlinks, never the submodule's worktree, unless
    recursing.
  rm <path>: refuses local modifications as measured; removes the
    gitlink, the worktree and the `[submodule]` section of .gitmodules
    (staging it; an emptied .gitmodules stays, empty); keeps
    .git/modules/<name>; --cached keeps the worktree (`?? <p>/`); -f forces.
  mv of a submodule, restore of a gitlink path and stash with submodules
    stay named refusals.
  push under submodule.recurse=true or push.recurseSubmodules other than
    no: a named refusal (R-vc25-3); `--no-recurse-submodules` and
    `--recurse-submodules=no` push as today.
Hostile and odd inputs (item 8), each red first:
  a name with a `..` component: `warning: ignoring suspicious submodule
    name: <name>` (twice in clone and status, as Git prints it), the entry
    ignored; a `.gitmodules` path with `../` never matches a gitlink (the
    entry is ignored, the gitlink has no mapping); a URL or path beginning
    with `-`: `warning: ignoring 'submodule.<name>.url' which may be
    interpreted as a command-line option: <value>`, then `fatal: No url

    missing on the remote: the upload-pack refusal relayed, then the
    direct-fetch fatal, exit 128, superproject kept; a gitlink with no
    entry: `fatal: No url found for submodule path '<p>' in .gitmodules`
    (update) and `fatal: no submodule mapping found…` (status), exit 128;
    an invalid .gitmodules: `fatal: bad config line <n> in file
    <absolute>/.gitmodules`, exit 128, in clone, status and update; a
    missing url: as no entry; case-colliding paths: both cloned on Linux,
    as Git does there (the macOS leg records the field Git); a symlinked

R-vc25-5 (ls-tree, ls-files): den has neither; (a) bounded forms here,

R-vc25-6 (describe for submodule status): (a) an internal describe subset

R-vc25-7 (update modes): checkout only; none honoured as a skip;
