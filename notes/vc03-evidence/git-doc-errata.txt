1. Longer whole-component star runs behave as globstars

Git v2.56.0 Documentation/gitignore.adoc, PATTERN FORMAT, states:
"Other consecutive asterisks are considered regular asterisks and
will match according to the previous rules."

With .gitignore containing a/***/file and files a/file and a/d/e/file,
`git check-ignore -v --no-index a/file` exits 0 and writes exactly:
.gitignore:1:a/***/file<TAB>a/file<LF>

The corresponding query for a/d/e/file also exits 0 and prints the same
pattern and that pathname. Both stderr streams are empty. The three-star
component therefore matches zero or multiple directory components, unlike
an ordinary star confined to one component.

Suggested documentation correction: describe runs of two or more stars at
these whole-component globstar boundaries, if the observed behavior is intended.

2. Verbose negative matches have success status without exclusion

Git v2.56.0 Documentation/git-check-ignore.adoc, EXIT STATUS, states:
0: "One or more of the provided paths is ignored."
1: "None of the provided paths are ignored."

With .gitignore containing !file and a file named file,
`git check-ignore --no-index file` exits 1 with empty stdout/stderr.
`git check-ignore -v --no-index file` exits 0 and writes exactly:
.gitignore:1:!file<TAB>file<LF>
Stderr remains empty. The negated rule matches, but the file is not ignored.

Suggested documentation correction: distinguish a verbose matched rule
(including negation) from a nonverbose positive exclusion in EXIT STATUS.

Den follows these measured binary behaviors under adopted R-vc03-4 A. These
are documentation reports for review, not upstream submissions or issue filings.

3. Relative core.excludesFile source spelling is not made absolute

Git v2.56.0 Documentation/git-check-ignore.adoc, OUTPUT, says <source> is an
absolute path for core.excludesFile. With core.excludesFile=relative.ignore,
the actual verbose result is:
relative.ignore:1:*.tmp<TAB>scratch.tmp<LF>
The source spelling remains relative, even when check-ignore runs from a
subdirectory. Lookup remains rooted at the worktree rather than that subdirectory.
Reproducer: tools/ignore-filesystem-oracle.py, global-relative cases; original
captures are in ignore-filesystem-initial.json. Adopted R-vc03-6 follows the
binary and separates lookup path from displayed source spelling.
